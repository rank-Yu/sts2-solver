# Mod 安装与构建

[返回文档索引](README.md)

本文讲发布包里有什么、怎么构建正式版和测试版、设置文件、战斗面板，以及 Mod 在游戏里的线程分工。玩家用法（自动搜索与执行本场战斗、什么时候停止）见仓库根的 [README](../README.md)；控制器的决策与核对流程见 [战斗自动执行与核对](autoplay.md)。

## 安装包

把 `Sts2Solver/` 目录放进游戏的 `mods/` 目录。包里有 `Sts2Solver.dll`、`Sts2Solver.json`、`LICENSE` 和 `README.md`，不含游戏文件，也不含 RitsuLib，RitsuLib 由玩家另装。

- 兼容性：当前适配游戏 v0.111.0，清单要求 RitsuLib 至少 0.6.0。
- 与 CombatSolver 共存：两个都正常启用，玩家可以都用来搜索，但每回合只能让一个执行。检测到 CombatSolver 已加载或等待加载时只写一行 `COEXIST` 日志，并把回合准备页面的接管限制在“执行本场战斗”进行中（其余时候放行这个页面，出牌阶段照常搜索）；选牌页面的挂钩只在本 Mod 自己的回合准备会话里起作用，平时只观察不干预。两个求解器同时执行（自动出牌或代选）会互相干扰，本 Mod 发现选牌或局面对不上时按偏差暂停并交还手动操作。
- 第三方内容不在支持范围内，导入时会明确拒绝。
- 状态和错误写进游戏日志，条目前缀是 `[Sts2Solver]`。

## 两种构建

正式版只有战斗功能；测试版额外编入场景注入、状态捕获和无头测试补丁。游戏与 RitsuLib 的路径写在被 git 忽略的 `src/Mod/local.props`（模板 `local.props.example`）；Import 和测试宿主的游戏路径来自 `tests/Differential/local.props`。

```bash
# 正式版
dotnet build src/Mod -c Release

# 测试版
dotnet build src/Mod -c Release -p:EnableModTesting=true
```

| 项目 | 正式版 | 测试版 |
| --- | --- | --- |
| 打包目录 | `artifacts/mod/Sts2Solver` | `artifacts/mod-testing/Sts2Solver` |
| 中间文件与程序集 | `artifacts/obj`、`artifacts/bin` | `artifacts/testing/obj`、`artifacts/testing/bin` |
| Core、Import、战斗执行 | 相同源码 | 相同源码 |
| TestHost、测试入口与补丁 | 不编入 | 编入 |
| `STS2_SOLVER_TEST_DIR` | 不读取 | 设置后进入测试循环 |

游戏加载器只加载与清单 ID 同名的 DLL，所以 Core 与 Import 的源码直接编入 `Sts2Solver.dll`，不附带其它求解器 DLL。两种构建的 Mod ID 相同，不要同时安装。构建只写仓库里的 `artifacts/`，不碰玩家的游戏目录。测试版入口只在显式测试模式下注册测试补丁；正式版既没有测试补丁目录，也没有补丁注册逻辑。

不加载游戏就能检查两种包的编译边界（类型与程序集引用）：

```bash
dotnet run --project tests/Architecture -c Release --no-build -- --mod artifacts/mod/Sts2Solver/Sts2Solver.dll
dotnet run --project tests/Architecture -c Release --no-build -- --testing-mod artifacts/mod-testing/Sts2Solver/Sts2Solver.dll
```

测试版的无头运行方法见 [测试与验证](testing.md#9-实机无头测试)。

## 设置文件

设置保存在 Godot 用户目录下的 `user://sts2solver/settings.json`；实际路径由游戏的用户数据目录决定。文件不存在时使用默认值，第一次修改设置时创建。文件顶层的 `schemaVersion` 当前是 `7`；写入先写 `.tmp` 再原子替换。

设置文件接受当前 `schemaVersion=7`。`schemaVersion=6` 的文件读入时只换算自动化档位：`automation.mode` 为 `Manual` 时自动搜索关，`AutoSearch`、`FullAuto` 时开，其余设置原样保留并写 `SETTINGS_UPGRADED` 日志；更早的版本或未知字段按下面的通用损坏路径处理。

每次保存记一行 `SETTINGS_SAVED`，`changed=` 列出变化的设置，形如 `search.tier:ExtraHigh->Medium`（数组整体比较，没有变化写 `-`），战斗日志的 `events.log` 也会收到这一行。文件在 Mod 初始化时读取，直接修改文件需要重启游戏；运行中通过面板的设置页或策略侧栏修改后，搜索设置在下一次搜索开始时生效。JSON 损坏或字段校验不通过时，文件会改名为同目录的 `settings.bad-<UTC 时间>.json`，记录 `SETTINGS_CORRUPT`，然后用默认值继续，不阻止游戏启动；其他读取失败记录 `SETTINGS_LOAD_FAILED`，同样用默认值继续。旧文件里的未知字段不会被静默忽略。

默认值与当前行为一致。设置按搜索、自动化、界面三个分区保存：

| 字段 | 默认值 | 含义 |
| --- | --- | --- |
| `search.tier` | `Medium` | 搜索档位：`Low`、`Medium`、`High`、`ExtraHigh`。下一次搜索开始时生效，已经开始的搜索不变。 |
| `search.memoryBudgetBytes` | `null` | 搜索内存上限（字节）。`null` 表示按下面的优先级解析。 |
| `search.threads` | `null` | 一个搜索成员的总线程数（含搜索线程本身）；`null` 表示按逻辑核数自动决定。 |
| `search.potions.defaultMode` | `Smart` | 药水默认策略；请求捕获只接受 `Smart` 和 `Disabled`。 |
| `search.potions.preset` | `Smart` | 药水预设，只在批量命令中更新；不是搜索输入。 |
| `search.potions.directives` | `[]` | 逐槽策略，每项是 `{ "slot", "potionId", "directive" }`。搜索接受 `Smart`、`Disabled` 和 `Force`；`Smart` 不入表。 |
| `search.growthBudgets` | 十个来源全为 `0` | 十个内置成长来源的额外战损预算。文件里的第三方来源条目原样保留，但不进入请求。 |
| `search.relicCounterAllowances` | `{}` | 计数遗物的额外战损额度：键是原版遗物 id（如 `PEN_NIB`），值 0–1000，没有条目按 0。只接受十个计数遗物，见下文遗物页。 |
| `search.ignoreLongTermRewards` | `false` | 不考虑局外收益。 |
| `search.brightestFlameMaxHpLossLimit` | `null` | 至亮之焰整场累计最大生命消耗上限；`null` 不限，`0` 表示不再打出，范围 0–1000。 |
| `search.actTransitionBossHpStrategy` | `ProgressionFirst` | 第一、二幕 Boss 的血量策略，另一取值是 `MinimizeHpLoss`。 |
| `search.finalBossHpStrategy` | `ProgressionFirst` | 最终 Boss 的血量策略，另一取值是 `MinimizeHpLoss`。 |
| `automation.autoSearch` | `true` | 自动搜索开关：每个玩家回合开始时自动搜索。跨战斗、跨重启保留；“执行本场战斗”只属于当前战斗，不写设置。 |
| `automation.deploymentSpeed` | `FollowGame` | 自动出牌速度：`FollowGame`、`Normal`、`Fast`；执行期间临时覆盖游戏战斗速度，结束后恢复。 |
| `automation.interActionDelaySeconds` | `0` | 两张牌之间的额外停顿，范围 0–3 秒。 |
| `ui.panelX`、`ui.panelY` | `null` | 主面板位置；两个值同时存在或同时为空。 |
| `ui.panelWidth`、`ui.panelHeight` | `null` | 主面板尺寸；两个值同时存在或同时为空。 |
| `ui.collapsed` | `false` | 主面板是否收起。 |
| `ui.opacity` | `0.65` | 主面板透明度，范围 0.25–1。 |
| `ui.showBattleDamagePerformanceHint` | `true` | 是否显示“本场战斗出现大战损”提示；玩家点击提示后写为 `false`，之后不再显示。 |
| `ui.theme` | `Dark` | 旧文件的兼容字段；面板固定深色，不提供浅色主题。 |

接入运行逻辑的是搜索档位、内存上限覆盖、搜索线程数、`automation` 分区、`ui` 分区，以及药水逐瓶策略、成长额度/不考虑局外收益、遗物计数额度、至亮之焰上限和两项 Boss 血量策略。药水指令按 `(槽位, 药水 id)` 生效；进入战斗时对不上的旧项会从设置文件删除，新药默认智能。策略改动只影响下一次搜索，不会自动重搜。盗贼策略不写入设置文件，只在当前战斗的会话状态里存在。

搜索内存上限按以下优先级解析：

1. 设置里的 `search.memoryBudgetBytes`；
2. 默认为运行时可用内存（物理内存或容器限制）的 20%，下限 1 GiB。

解析结果写入 `SEARCH_MEMORY source=settings|default` 日志。这个预算限制搜索自己的逻辑存储，不是游戏进程的 RSS；细节见 [战斗搜索](combat-ai.md#7-内存与容量)。

搜索线程数按以下优先级解析：

1. 设置里的 `search.threads`；
2. 默认取 `clamp(逻辑核数 - 2, 1, 8)`。

设置值夹到 1..8。设置值在每次搜索开始时重新读取，因此会话中修改 `search.threads` 会在下一次搜索生效。N 是一个成员内的总线程数，包括搜索线程本身，即 N−1 个工作线程加搜索线程；它不改变成员调度、评分或路线选择。

展开工作区按线程持有，不计入搜索内存上限。每个工作区的可变缓冲默认上限 8 MiB，N 线程时窗口取 2N 个工作区，因此可变部分上界约为 2N×8 MiB；每个工作区另有约 134 KiB 的固定草稿，固定部分合计约 2N×134 KiB。N=8 时可变部分上界约 128 MiB，合计约 130 MiB。细节见 [战斗搜索](combat-ai.md#5-单个成员内部)。

自动搜索开关只决定每个玩家回合开始时要不要替玩家按一次搜索；执行永远由玩家按下“执行本回合”或“执行本场战斗”开始。开关持久保存，拨动它不开始也不停止执行。停止搜索、停止执行和本场执行的暂停都只管本回合或本场，不改开关。首次安装默认开，因此进入战斗会开始搜索，但不会自动出牌。

## 战斗面板

单人战斗进行中，屏幕左上方显示“尖塔求解器”面板；战斗结束、离开战斗或处于多人会话时隐藏。面板只在主线程读取只读快照，按钮只经由 `ICombatUiCommands` 下发命令，不直接调用搜索、`SearchSession` 或游戏动作。面板每帧读取快照，只在快照或本地呈现状态变化时更新控件；内容相同的路线行沿用原有控件。

面板从上到下分为：

- **标题栏**：左边只有产品名“尖塔求解器”，右侧依次是“药水”“成长”“遗物”“设置”和“收起”。“药水”“成长”“遗物”打开停靠在面板旁边的策略侧栏，“设置”把面板主体换成设置页，见下文。收起时标题栏和底栏仍然可用，“药水”“成长”“遗物”“设置”隐藏。按住标题栏可以拖动面板，右边缘、下边缘和右下角可以缩放；松开鼠标后，位置和尺寸写入设置文件的 `ui.panelX`、`ui.panelY`、`ui.panelWidth`、`ui.panelHeight`。面板使用原版的展开宽度 560–820、展开高度上限 440（设置页显示时 540）、收起尺寸 520×120，始终限制在窗口内；展开时不会窄于标题栏的内容，英文按钮更宽，最小宽度因此略大于 560。收起状态写入 `ui.collapsed`。
- **提示条**：标题栏下面依次是盗贼提示条、搜索上限提示和大战损提示，每条至少 44 高，面板随之变高。盗贼提示条只在有偷窃敌人的战斗出现（判定同原版），写“本场有盗贼：保住被偷的牌和金币”和按钮“改为放走”；点按钮后写“本场有盗贼：放走，不追回被偷的牌和金币”和“改为保住”。它只改本场的盗贼策略，下一次搜索生效，不写设置文件，每场战斗开始时回到保住；收起时照样显示。搜索上限提示只在本轮搜索因时间或节点上限提前结束时出现，文案按稳定边界码选择。大战损提示在本场预计战损至少 8 HP 时出现；点击后写入 `ui.showBattleDamagePerformanceHint=false`，永久不再显示。设置页显示时隐藏盗贼提示条和大战损提示，搜索上限提示照常显示。
- **状态摘要**：状态文字、上下文、摘要和统计行。“执行本场战斗”的回合间搜索和搜到就执行的重算，搜索中的上下文后面加“已排队执行”（照搬原 CombatSolver）。上下文只写回合、已规划到的回合或暂停原因，不显示生命。回合准备页面打开、还没有计划时显示“等待回合开始选择”；沿用上一回合计划时也显示“等待回合开始选择”并保留路线；准备搜索中沿用“后台搜索中”；新搜索出的准备计划就绪显示“方案就绪”；求解器正在页面上点选时显示“正在执行”。搜索中显示“后台搜索中”和从这次搜索开始算起的已用时间（面板没有进度条）；摘要先显示“正在搜索当前回合，等待可存活候选… │ 已查阅 N 条世界线”，有候选后改为“候选摘要 │ 已查阅 N 条世界线（S 条/s）”。已查阅世界线按整场累计：本场之前各次搜索（包括被取消的）加上这次搜索已完成成员和当前成员的展开数，换成员时不会回落；速度按主线程时钟在相邻两次进度之间测量，世界线和速度按指数平滑滚动。搜索结果就绪时显示“方案就绪 / 方案已复用 / 重算后战损上升”，摘要为“本回合结束战斗”或“预计路线 N 回合”，统计行为“花费了 X 秒，共查阅了 N 条世界线（S 条/s）”。执行中显示“正在执行”，每步更新为“正在执行 k/N：卡名”，结束回合时改为“正在执行： 结束回合”。搜索或导入失败时状态行显示“求解器消息”，摘要第一行显示对应错误文案、第二行显示结构化原因（没有映射时写“详细原因已写入日志”），路线隐藏，执行键变灰。动作或局面偏差、部署失败暂停时摘要同样是“暂停标题 + 一行具体原因”。
- **路线**：第一行是结果的起始回合；复用的路线从当前回合开始；执行完成后、下一回合结果出来之前，第一行仍是刚执行的那一回合。最多显示 16 行，超出时在摘要末尾注明“另有 N 回合未展开显示”，不显示更早的回合。每个回合行先显示该回合的起手选择胶囊：根回合用本次准备计划，后续回合用前一个 EndTurn 动作里 `PlayerTurnStart` 时机的选择；来源写成游戏内的遗物、能力、卡牌或药水标题，中英文跟随游戏语言，取不到来源时写“起手选择”，知识诅咒不显示。动作胶囊左侧色条区分攻击、技能、能力、状态或诅咒、药水；胶囊上写目标、选牌、击杀和重放次数，悬停显示生命与能量变化。连续重复至少三次的动作折叠成“循环 ×N”。执行中的动作高亮，已执行的动作变暗；面板每次刷新只更新进度，颜色和高亮动画只在换成新的展示（开始执行某一回合、显示结果或执行历史）时重置，已执行的动作不会每刷新一次就重新淡出一遍；同名敌人的“#序号”在一场战斗里固定，有敌人死亡后其余敌人不重新编号；动作结算完、下一个动作开始前不点亮，折叠循环在重复期间保持同一颗胶囊高亮、跑完最后一次才算完成；当前回合的行带蓝色强调标记。本场执行进入下一回合的回合开始选择页（等待沿用的选择或正在点选）时，路线仍按执行中的方式显示：刚执行完的那一回合保持已执行，当前回合这一行带强调标记。行尾依次是对敌伤害、本回合生命变化和结束回合时剩余的能量。结束回合只在造成击杀、或者整回合只有结束时单独画出。搜索中显示当前成员目前最好的路线：本成员已经打完的最好路线（胜利或死亡）和前沿上还没打完的候选一起按最终排序比较，所以一个成员搜到胜利后，预览就停在那条胜利上，不再显示前沿上的半截路线；按原 CombatSolver 协调器的规则，一旦显示过胜利候选，后续成员的候选只有同样胜利且失血更少（失血相同则用药不多于它）才替换，避免新成员刚开始的较差候选让预计失血忽高忽低。“只找到死亡路线”只在搜索结束后的结果里显示。搜索中“本局扣血”的“已”是搜索根之前已经损失的生命，“预计”是它加上候选路线的损失。路线标题右侧依次是已用药、预计用药、预计未追回、策略结果、本局扣血（“已 X 预计 Y HP”）和回血：路线中的回血写“路线回血”，胜利路线结束后燃烧之血、黑暗之血、带骨肉（战斗结束时不高于阈值才回）恢复的生命写“战后遗物回血”，不超过结束时缺失的生命；两者都有时并排显示。路线排序也按这部分回血后的生命比较，所以带骨肉的回血比多掉的血多时，路线会停在阈值上。用药照搬原 CombatSolver：本场还没喝过药时写“预计用药：2瓶（火焰药水、格挡药水）”；喝过以后另写黄色“已用药：1瓶（…）”（游戏战斗历史里本场喝过的药，结果生成或下一回合沿用路线时取），路线里的写成“还要用：1瓶（…）”；搜索中的预览只写“预计用N瓶药”。盗贼战里路线结束时盗贼手里还有牌或金币，写红色“预计未追回：N 张牌 / G 金币”。本局扣血左边是策略结果（照搬原 CombatSolver）：绿色“已卡：开心小花 2”列出胜利路线结束时计数正好停在目标上的遗物，黄色“未达标：开心小花 2 实际 0”列出没对上的（目标和结束时的值），绿色“已获得：炼制药水 ×2”列出本场到路线结束为止拿到的成长收益；没有计数目标也没有成长收益时不显示，搜索中不显示；带骨肉的回血写在“战后遗物回血”里，不在这里重复。执行中控制器已经交出当前结果，这几项读正在执行（或刚执行完）的那份结果，所以执行时不会变成“预计战损 未知”。
- **底栏**：一行从左到右是自动搜索开关、搜索键、执行键，下面是内存条。显示哪些键只看本回合的搜索和执行进行到哪一步（快照的 `SearchStage`），不看有没有搜到路线：
  - 搜索键：本回合还没开始搜索（也没有沿用或激活路线）时是“开始搜索”；搜索中是“停止搜索”（危险色）；停下或跑完之后是并排的“继续搜索”和“重新搜索”，由玩家选。“继续搜索”只在停止后局面和搜索设置都与停止时一致时可按，否则变灰并写原因（“局面或搜索设置变了，只能重新搜索。”或“这次搜索已经跑完，没有可以继续的部分。”）；沿用的路线也算跑完。回合准备页面上“重新搜索”在同一个页面上重算（沿用的计划会改为重新枚举和搜索）。不能搜索时变灰，悬停写原因（敌方回合、动作结算中、回合开始结算中、等待回合开始选择、正在执行）。
  - 执行键：平时“执行本回合”和“执行本场战斗”固定在原位，没有与实机一致的本回合路线（或回合准备计划）时变灰并写原因（“还没有搜索。”或“没有可以执行的本回合路线。”）。“执行本回合”只执行这一回合；“执行本场战斗”执行这一回合，之后每回合自动搜索（或沿用）并执行，直到战斗结束。本场执行自己暂停后，“执行本场战斗”的悬停改为确认继续，按下后这一回合跳过刚才那项暂停检查，后面的回合照常检查。准备页面上按执行键会驱动页面，选完后接着部署。
  - 搜索中（包括回合准备页面上的搜索）执行区什么都不显示，想提前执行就先停止搜索，停止会留下最优路线。执行中（执行本回合、执行本场战斗包括回合间的搜索、在回合准备页面上驱动、计划用尽后搜到就执行的重算）执行区只有“停止执行”（危险色），搜索键变灰；按下后整场停下，交回玩家。
  - 自动搜索开关随时可拨：回合中途打开时，如果本回合还没搜索过、当前可以搜索，就立刻开始搜索；关掉不影响正在跑的搜索。
  下方内存条整条代表搜索内存上限；搜索中填充当前搜索用量，标签写“搜索内存 已用 U / 上限 B GB · 游戏占用 X GB”，搜索结束后保留本场最近一次搜索的峰值，标签写“搜索内存 峰值 P / 上限 B GB · 游戏占用 X GB”（超过上限时为危险色），本场还没有搜索时写“搜索内存上限 B GB · 游戏占用 X GB”。搜索上限只约束求解器自己的搜索存储，不是游戏进程的内存上限；展开工作区不计入这个上限。

本场执行的暂停条件按战斗自动执行一节生效。暂停时状态行按原因显示“已暂停执行 / 第 N 回合    预计死亡”、“已暂停执行 / 第 N 回合    未找到生还路线”（摘要写预计死亡回合，并提示提高搜索档位或点“执行本场战斗”继续）、“已暂停执行 / 第 N 回合    实机复核将死亡（或实机复核战损上升）”；偏差停下时状态行显示“已暂停执行”，摘要写“动作结果与预测不同，已停止”“回合开始时实际状态与预测不同，已停止”“实际局面与路线不符，已停止”或“自动执行中止”。暂停后本场执行结束，后续回合按自动搜索开关搜索，但不再自动执行。实机复核暂停发生在结束回合之前，剩余计划（只剩结束回合）保留为本回合路线：“执行本回合”强制执行这一回合，“执行本场战斗”确认后继续；偏差或部署失败暂停丢弃剩余路线，搜索键可用，执行键变灰。停止搜索和停止执行显示原版的“搜索已停止”两条文案：有保留路线时写“下方保留停止时已经得到的当前候选路线”，没有时写“本回合搜索已停止”。

没有战斗快捷键；面板只能收起，不能完全隐藏。注入 F8 或 Ctrl+F9 都不会改变面板状态。

暂停码只有这些稳定值：`death_turn`、`no_survival`、`live_end_turn_risk`、`repeated_failure`、`choice_mismatch`、`action_deviation`、`boundary_deviation`、`deployment_deviation`、`deploy_failed`、`stopped`。不能搜索的原因写入快照的 `SearchBlockReason`：`enemy_turn`、`turn_start`、`actions_running`、`turn_setup`、`executing`，以及不在战斗、多人、不可玩等拒绝码。

搜索或导入失败的阶段是 `Failed`，错误码写入快照的 `ErrorCode`，例如 `import_failed`、`import_unsupported`、`import_capacity`、`request_invalid`、`route_invalid`、`route_unsupported`、`route_capacity`、`search_failed`、`turn_setup_failed` 和 `forced_potion_unusable`。`turn_setup_failed` 只用于回合准备选牌，不是暂停码；失败后页面交还玩家，替换任务正常完成，原生 `StartTurn` 不进入 fault。主面板显示“求解器消息”和对应文案；失败状态在下一次搜索开始、回合变化、模式切换或战斗结束时清除。

### 策略侧栏

点“药水”“成长”或“遗物”打开策略侧栏的对应页，该按钮显示按下状态（深底蓝字）；侧栏开着时点另一个按钮换页，点已按下的按钮、点侧栏右上角的“×”或收起面板都会关闭侧栏。点侧栏外面不会关闭，每场战斗开始时侧栏是关着的。设置页显示时点这三个按钮，先回到路线再打开侧栏。侧栏没有页签，标题行是页标题（药水策略 / 成长策略 / 遗物策略）和“×”。侧栏宽 390，停靠在面板右侧；右侧放不下时放左侧，两侧都放不下时贴着空间较大一侧的屏幕边缘。侧栏顶边与面板对齐，高度等于面板的实际高度，拖动和缩放面板时跟着移动。内容超出高度时竖向滚动，不横向滚动。侧栏不随面板透明度变化。

各页的改动都经 `ICombatUiCommands` 立即保存，页底状态行写“已保存，下次搜索生效”；不会自动重新搜索，进行中的搜索和已显示的路线不变。

**药水页**：上方一排三个批量按钮“全部智能 / 全部保护 / 全部强制”，下方每个有药水的槽位一行：药水图标、“#槽位 药水名”和模式按钮。模式按钮按“智能使用 → 禁用 / 保护 → 强制使用 → 智能使用”循环，文字分别是灰、红、绿色；按钮宽度取三种文字里最宽的，换档时不跳。禁用和保护是同一档。不能指定策略的药水（例如瓶中精灵）按钮禁用，悬停写“该药水不可指定使用策略”；显示“智能使用”的按钮悬停说明智能使用的门槛。批量按钮只改当前可指定策略的药水，“全部保护”写禁用。原 CombatSolver 还有“仅用已强制”（保留已强制的药水、其余改为禁用），这里没有：先点“全部保护”再把要用的药水点成强制，结果相同。没有可指定策略的药水时三个批量按钮都禁用；药水栏为空时写“当前没有药水”。

强制使用是硬要求：搜索找不到用掉全部“强制使用”药水的路线时，这次搜索显式失败，快照错误码是 `forced_potion_unusable`，摘要写“找不到用掉所有“强制使用”药水的路线，请在药水策略里调整后重新搜索”。

**成长页**：依次是“不考虑局外收益”开关、“限制至亮之焰的最大生命消耗”开关和“每场最多消耗”，再是分组“每次收益允许的额外战损”下的十个内置来源（贪婪之手、狩猎、狂宴、王国资产、炼制药水、遗传算法、巨镰、黏糊防御、禁忌魔典、疯狂科学）。每行有游戏卡图、名称和带 HP 后缀的输入框；输入 0–1000 的整数，回车或离开输入框时保存，0 显示为灰色。填错时文字变红，状态行写“请输入 0–1000 的整数”，侧栏不关闭、不换页。打开“不考虑局外收益”后十个来源变灰、不可编辑，至亮之焰限制照常可用。限制开关关闭时“每场最多消耗”变灰并显示 2；打开开关写入 2，之后可以改，关闭写入 `null`（不限）。悬停说明只挂在“每场最多消耗”（标签和输入框）以及分组标题和十个输入框（同一句）。第三方成长来源不列出。

**遗物页**：分组“允许的额外战损”下，每个持有且未融化的计数遗物一行：游戏图标、名称、“当前 x/周期”和带 HP 后缀的输入框，按遗物栏顺序排列。计数遗物是计数能带进下一场、而且出牌或回合数能调整的十个：开心小花、开心小花？？？、摆动球、花粉核心、钢笔尖、双截棍、音叉、金纸、铁棒、星系尘埃。搜索的目标固定为战斗结束时计数差一次触发（例如钢笔尖停在 9、开心小花停在 2），下一场第一次机会就触发，目标不能改。额度是为对上目标愿意多掉的血，每个遗物每场最多算一次，默认 0：0 只在不多掉血时对齐。输入规则和成长页相同。打开成长页的“不考虑局外收益”后各行变灰、不可编辑，搜索不设目标；跑局的最后一战也不设目标。没有计数遗物时写“当前没有计数遗物”。带骨肉不在这一页，胜利路线一律按战后回血后的生命比较。

### 设置页

点“设置”把面板主体（状态摘要、路线、底栏）换成设置页，按钮字变成蓝色的“返回”；按钮宽度取两者较宽的，换字时标题栏不变宽窄。点“返回”回到路线。打开设置页会关闭策略侧栏。收起面板保留设置页状态，再展开仍是设置页；每场战斗开始时设置页是关着的。设置页有非法输入时，“返回”、收起和切到“药水”“成长”都不生效，焦点留在该输入框。设置页显示时，面板按设置页的完整内容请求高度，最高 540，放不下时竖向滚动；拖过大小时用拖出的尺寸。

设置页是面板里的一个深色框：标题行“求解器设置”和“恢复默认”，下面五组。前四组两列，改动立即保存；第五组“反馈”只有一个按钮，见本节末尾。

| 组 | 设置 | 字段 | 何时生效 |
| --- | --- | --- | --- |
| 出牌 | 自动出牌速度：跟随游戏 / 正常 / 快速 | `automation.deploymentSpeed` | 下一次执行 |
| 出牌 | 牌间额外停顿（秒）：0–3，留空为 0 | `automation.interActionDelaySeconds` | 下一次执行 |
| 性能 | 性能预设：低档 / 中档 / 高档 / 极高 | `search.tier` | 下一次搜索开始时 |
| 性能 | 搜索并行度：整数 1–8 | `search.threads` | 下一次搜索开始时 |
| 性能 | 搜索内存上限（GB）：0.25 到运行时可用内存，精度 0.1 GB | `search.memoryBudgetBytes` | 下一次搜索开始时 |
| Boss 策略 | 第一、二幕血量取舍：通关优先（默认）/ 最低战损 | `search.actTransitionBossHpStrategy` | 下一次搜索开始时 |
| Boss 策略 | 最终 Boss 血量取舍：通关优先（默认）/ 最低战损 | `search.finalBossHpStrategy` | 下一次搜索开始时 |
| 显示 | 覆盖层透明度：25%–100% | `ui.opacity` | 立即预览；停止拖动 0.4 秒后保存；作用于整块面板 |

搜索并行度和搜索内存上限的输入框预填当前生效的值，没有设置过时就是本机默认值（并行度为逻辑核数 − 2，夹到 1..8；内存上限为运行时可用内存的 20%，至少 1 GiB）。没有改动的输入不写设置；输入等于本机默认值（内存上限按 0.1 GB 比较）或清空时写入 `null`，之后继续跟随本机默认。GB 按 10⁹ 字节计，与内存条一致。输入不合法时文字变红，底部状态行写出允许范围，输入框保持焦点。保存后底部状态行写“已保存，下次搜索生效”“已保存，下次执行生效”或“已保存并立即生效”。两项幕末 Boss 经 `ICombatUiCommands` 保存。有悬停说明的只有性能预设、搜索并行度、搜索内存上限和两项幕末 Boss，各组不写说明文字。

“恢复默认”恢复本页各项（出牌速度、牌间停顿、档位、并行度、内存上限、两项 Boss 策略、透明度），同时把面板位置和尺寸恢复为默认，并重新打开大战损提示；自动搜索开关不变，开关只在底栏拨动。药水和成长没有恢复默认。面板固定深色，没有主题选择；`ui.theme` 只为读取旧文件保留。大战损提示的持久字段没有控件，只由提示本身和“恢复默认”写入。

“反馈”组只有“导出战斗日志”按钮，悬停写“遇到问题时可导出发给作者”。点击后按钮变灰，状态行写“正在导出…”；后台把最新的两场战斗（通常是本场和上一场）打成 zip 放进战斗日志目录的 `exports/`，然后状态行写“已导出 <文件名>”，并在系统文件管理器里定位这个文件（测试模式不打开）。失败时写“导出失败，详情已写入游戏日志”，日志记 `COMBAT_LOG_EXPORT_FAILED`。导出只生成本地文件，不上传；“恢复默认”不涉及这一组。

### 语言与字体

游戏语言为简体或繁体中文时面板显示中文，其他语言显示英文。英文文案在 `src/Mod/UI/English.json`，键是中文源串。切换游戏语言后面板整体重建，文字、提示、路线行和卡片名称都换成新语言。中文、日文、韩文、俄文等使用游戏自带的替换字体；其余语言不额外覆盖字体，使用游戏主题字体。切换语言时面板整体重建。

## 战斗日志

每场单人战斗在 `user://sts2solver/combat-logs/<UTC 时间>-<遭遇 Id>/` 下建一个目录（Mac 上即 `~/Library/Application Support/SlayTheSpire2/sts2solver/combat-logs/`），一直记录，没有开关：

- `combat.json`：Mod 版本、游戏版本、角色、遭遇、房间类型、幕、楼层、进阶和界面语言。
- `search-NNN.json`：每次出牌搜索或回合准备搜索的种类、回合、原因、是否续搜、档位、线程数、搜索计划、状态、选中的成员、耗时、展开数、选中路线的文字描述，以及每个成员的宽度、评价方式、保留方式、用药阶段、运行或跳过原因、耗时、展开数、截止检查序号（成员内第几次截止检查发现到期，未到期为 0）、停止原因、胜负、预计掉血、用药数和是否采用。请求编好、搜索开始时就先写一份，状态和完成方式都是 `Running`，成员为空；搜索结束后用同一个编号补全。所以搜索中途被取消（战斗结束、局面已变）时仍留有请求和计划，状态停在 `Running`。导入失败等没有请求的情况在 `events.log` 里。
- `search-NNN.sreq.br`、`search-NNN.sres.br`：交给协调器的基础请求（SREQ，搜索开始时写）和最终选中的结果（SRES，搜索结束时写），Brotli 压缩。
- `deviation-NN.json` 与 `.predicted.batl.br`、`.actual.batl.br`：出牌偏差、结束回合偏差、续用边界偏差和回合准备开局预测不符时，预测与实际的 `Battle` 以及差异行。
- `events.log`：本场开始后的 `[Sts2Solver]` 日志行，战斗结束到下一场开始之间的行也记在这里。

只保留最新 20 场，新战斗开始时删除更早的目录；`exports/` 最多保留 10 个导出包。主线程只编码和入队，一个后台线程按顺序写盘，导出也排在同一个队列里，所以导出时本场已有的记录都已写完。写盘失败只在游戏日志写一次 `COMBAT_LOG_WRITE_FAILED`，不影响搜索和执行；写盘线程遇到磁盘以外的异常会停止并记 `COMBAT_LOG_WRITER_STOPPED`，这时导出返回失败；请求编码失败记 `COMBAT_LOG_ENCODE_FAILED`，这次搜索只写摘要。测试模式写到结果目录的 `combat-logs/`。离线重放见 [测试与验证](testing.md#44-战斗日志重放)。

## 线程分工

入口订阅 RitsuLib 的战斗开始、结束事件和游戏的玩家回合开始事件。一次搜索分三段：

1. **主线程捕获。** 读取原版状态，由 Import 编译出 `Battle`、`Rules`、评分表和搜索配置。
2. **后台搜索。** worker 只访问上一步冻结的数据，按组合调度依次运行搜索成员。每个成员内部按搜索线程数并行展开动作层：搜索线程按父节点原顺序提交，工作线程只做展开计算。普通模式下会按游戏帧压力让出时间，所有工作线程共用一个帧压力信号；`Solve` 结束前把工作线程的让出和等待指标合并进主 pacer。确定性测试不挂让帧器，单次搜索默认只用 1 个线程。
3. **主线程执行。** 结果交回主线程，经内核重放确认路线有效后，通过游戏的动作入口执行并逐动作核对。

停止搜索时，协调器把已完成成员的最优结果和当前候选按最终排序比较，取更优的一条经重放校验后留作本回合路线；没有候选时取消后台搜索。停止在中间成员时还会带出一份只在主线程内存里的接续状态（第几遍、下一个成员、成员日志和当前成员状态），左槽据此显示“继续搜索”；点击时重新编译请求并和停止时的请求逐字节比较，一致才从下一个成员继续。接续状态在回合变化、开始执行、局面变化、战斗结束、退出场景和开始新搜索时作废。停止执行只是软停止：不再发出新动作，当前动作连同选牌、边界等待和稳定等待走完后返回，`_deployment` 在此之前保持非空。战斗结束、退出场景和重置会硬取消搜索与执行。切换档位不取消。界面只在主线程运行，读取的快照由主线程在上面三段的边界上发布；后台 worker 不接触快照和 Godot 节点。

战斗日志由单独的后台写盘线程负责，见上一节。

搜索内存预算的解析顺序见上一节；它限制的是搜索自己的逻辑存储，不是游戏进程的 RSS。展开工作区按线程单独持有，不计入这个预算。细节见 [战斗搜索](combat-ai.md#7-内存与容量)。
