# STS2 Solver · 尖塔求解器

《杀戮尖塔 2》的战斗求解 Mod，面向原版单人、同种子 SL 模式。它读取当前战斗和真实的随机数状态，搜索整场战斗的出牌路线，再通过游戏自己的操作入口自动出牌、用药，并逐个动作核对实际结果。

“同种子 SL”指同一个种子下存档读档：随机结果是确定的，求解器正是靠这一点预测每一步的结果。

本 Mod 只接管战斗；地图、事件、商店等局外操作仍由玩家完成。

## 安装

需要游戏 v0.111.0，以及兼容的 RitsuLib（清单要求最低 0.6.0）。

1. 单独安装 RitsuLib。
2. 把发布包里的 `Sts2Solver/` 目录放进游戏的 `mods/` 目录。

不要和 CombatSolver 同时安装：检测到 CombatSolver 时，本 Mod 不启用，以免两个求解器同时控制战斗。

## 使用

- 战斗面板标题栏有三段模式按钮：手动、自动搜索、全自动。手动档两个底栏按钮都由玩家按；自动搜索档每回合由求解器按“搜索”，玩家按“执行本回合”；全自动档两个键都由求解器按。切换档位不会打断正在进行的搜索或执行。
- 底栏只有两个槽：左边是搜索键（开始搜索 / 重新搜索 / 停止搜索），右边是执行键（执行本回合 / 停止执行，没路线时隐藏）。停止只管本回合，不改持久档位；下一回合照常按模式走。
- 档位跨战斗、跨重启保留，首次安装默认自动搜索。全自动遇到暂停条件时，本场不再自动执行，但持久档位仍是全自动，后续回合照常自动搜索；点标题栏“全自动”那一段恢复。下一场战斗照常全自动。
- 战斗中左上方显示求解器面板：搜索进度、整场路线、当前执行到哪一步。拖动标题栏移动，拖动边缘缩放；面板只能收起，没有显示/隐藏快捷键。
- 求解器执行时发现实际结果或局面和预测不符，或者部署动作无法执行，会立即停下并丢弃剩余路线，不自动重搜；玩家可以点“重新搜索”。选牌计划对不上时暂停并交还手动操作。
- 遇到不支持的内容（例如第三方 Mod 加入的卡牌）会明确拒绝，不会乱打。
- 搜索档位默认中档；出牌速度、牌间停顿、搜索档位、搜索并行度、搜索内存上限、幕末 Boss 血量取舍和面板透明度在标题栏“设置”打开的设置页里改；药水和成长策略在标题栏“药水”“成长”打开的侧栏里改；有盗贼的战斗在标题栏下方的提示条里选择保住还是放走。策略改动在下一次搜索时生效。没有设置并行度时按逻辑核数自动决定（逻辑核数 − 2，夹到 1..8）；没有设置内存上限时取运行时可用内存的 20%，至少 1 GiB。设置文件位置、默认值和字段说明见 [Mod 安装与构建](docs/mod.md#设置文件)，面板与三档说明见 [战斗面板](docs/mod.md#战斗面板) 和 [战斗自动执行与核对](docs/autoplay.md)。状态和错误写在游戏日志里，条目前缀是 `[Sts2Solver]`。

## 构建

需要 .NET 9 SDK。

不需要游戏文件的完整验证（内核合同、架构检查、冻结回归）：

```bash
tools/testing/verify-core.sh --jobs 8
```

冻结回归与基准一致只说明行为没变，不代表路线最优；搜索质量另由质量语料评估。

构建 Mod 本身需要本机的游戏文件，路径配置和正式版、测试版的区别见 [Mod 安装与构建](docs/mod.md)。架构、文档索引和术语见 [docs/README.md](docs/README.md)。
