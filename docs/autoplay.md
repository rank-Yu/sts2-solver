# 战斗自动执行与核对

[返回文档索引](README.md)

游戏里的战斗由 `CombatSessionController`（`src/Mod/Combat/CombatSessionController*.cs`）控制。它移植 CombatSolver `SolverController` 的交互状态机，负责自动搜索开关、本场执行、搜索请求、停止/执行、逐回合部署、暂停和快照；搜索、逐步执行和核对仍由 Sts2Solver 自己的 `SearchSession`、`ActionDeployer`、`BattleReconciler` 完成。`CombatPilot`（`src/Core/Autoplay/CombatPilot.cs`）只保留给 Differential 的离线整场评测，Mod 不再调用它的整场主循环。

路线续接、回合裁剪和偏差比较只有一份实现：`src/Core/Autoplay/CombatRoutePlan.cs` 的 `CombatRoutePlan`、`CombatRouteDecision`、`CombatStateStamp` 和 `CombatFullAutoPausePolicy`。游戏控制器和离线整场循环都调用它。

## 自动搜索与执行本场战斗

面板上只有两样东西决定求解器什么时候自己动手：

- **自动搜索开关**：保存在 `automation.autoSearch`，跨战斗、跨重启保留，首次安装默认开。开着时，每个玩家回合开始由求解器替玩家按一次搜索；只展示路线，不出牌。
- **执行本场战斗**：只属于当前这一场，不写设置，战斗结束就清掉（`_runCombat`）。玩家按下后执行本回合，之后每回合都先沿用上一条路线（对不上再搜索），再按“执行本回合”，直到战斗结束、暂停条件触发或玩家按“停止执行”。

不开自动搜索时，回合开始只做路线沿用：上一条路线还和实机一致就照样显示，可以直接执行；对不上就等玩家点“开始搜索”。

同一回合的回合开始只发出一次自动搜索；已经排上但还没执行的自动搜索在真正发出前重新检查开关，关掉后不再发出。

拨开关不会开始或停止执行，也不会替换一条仍然有效的路线。回合中途打开自动搜索时，只有本回合还没搜索过、也没有沿用路线、当前可以搜索，才立刻开始搜索（原因 `auto_search_switch`）；关掉开关不影响正在跑的搜索，要停就按“停止搜索”。

## 宿主与分工

| 场景 | 搜索 | 执行 | 核对 |
| --- | --- | --- | --- |
| 游戏 Mod | `CombatSearchRunner` + `SearchSession` | `CombatTurnDeployer` + `ActionDeployer` | `BattleReconciler`、`LiveCombatTracker` |
| 内核离线评测 | Differential 的离线宿主 | 在模拟内核里执行路线 | 只用于质量和性能评测 |
| 原版动作对照 | Differential 的 `NativePilotHost` | 用原版入口执行 | 检查原生终局 |

内核回放通过不等于原版动作对照通过，两类报告要分开写。

## 命令

界面只使用这些命令：

- `SetAutoSearch`：自动搜索开关。
- `StartSearch`：开始搜索 / 重新搜索，从头搜当前回合，丢弃停止时留下的接续状态；回合准备页面开着时重算页面计划。
- `ContinueSearch`：继续搜索。只有本回合停止过、而且局面和搜索设置都和停止时逐字节一致，才从下一个成员接着搜；否则拒绝（面板上这个键变灰）。
- `StopSearch`：停止搜索，把目前最好的路线留作本回合路线，不执行。
- `ExecuteCurrentTurn`：执行本回合，下一回合等玩家操作。
- `ExecuteCombat`：执行本场战斗。搜索中、执行中或本场执行已在进行时调用被拒绝；玩家先停止搜索（留下最优路线）再执行。
- `StopExecution`：停止执行。结束本场执行；正在执行的回合软停止，不再发出新动作，当前动作结算完后停下；正在驱动的回合准备页面停下；属于这次执行的搜索（回合间的搜索，或计划用尽后搜到就执行的重算）一并停下，留下最优路线。之后完全交回玩家。
- 策略命令：设置某个药栏位置的智能/禁用、全部智能/全部禁用、某个成长来源的额度、某个计数遗物的开关和额度、成长性卡牌收益开关、两项 Boss 血量策略，以及本场盗贼策略。

按执行键是玩家对这一回合的决定：之前的暂停或停止随之解除。执行本回合不开启本场执行，所以这一回合不做本场执行的暂停检查。执行本场战斗在本场执行自己暂停过之后按下，等于确认当前路线：这一回合跳过部署前暂停和结束回合实机复核（`_playerConfirmedTurn`），之后的回合照常检查；普通按下不跳过。

策略命令只在主线程写设置或本场会话状态并发布快照，不触发搜索。设置类改动在下一次搜索开始时生效；盗贼策略每场战斗重置为“保牌保钱”，不写入设置文件。

不能搜索的原因由控制器的 `CanSolve` 给出，写入快照的 `SearchBlockReason`：`enemy_turn`、`turn_start`、`actions_running`（动作队列未完成，含回合中的选牌界面）、`executing`，以及不在战斗、多人、不可玩等拒绝码。搜索键据此变灰并显示悬停原因；`StartSearch`、`ContinueSearch` 也检查同样的条件。没有路线时调用执行命令直接拒绝，不会先搜索。

快照的 `SearchStage` 告诉面板本回合搜到哪一步：`NotStarted`（本回合还没开始搜索，也没有沿用或激活路线）、`Running`、`Ended`（停止或跑完，沿用的路线也算）。底栏按这个阶段和是否在执行决定显示哪些键，不按搜索结果。

## 一次搜索

1. 玩家回合开始后，主线程一直等到进入 `PlayerTurnPhase.Play`（不设帧数上限），再等动作队列清空和回合开始的可视/计时协程结束。
2. 上一回合由求解器结束、并且那份路线里上一回合的 EndTurn 动作带有本回合 `PlayerTurnStart` 时机的选择时，回合准备页面直接沿用这份计划，不重新枚举、不搜索；见下一节。
3. 没有可沿用的准备计划时，不管自动搜索开没开，都先尝试沿用上回合路线：导入当前状态，和上一份完整路线的当前回合边界精确比较；一致就裁剪到当前回合直接复用，不搜索。上一回合由求解器结束、本回合又有续接路线但对不上时按 `boundary_deviation` 停下，不进入下一步。
4. 不属于偏差的续接失败（例如路线里没有本回合动作，或上一回合不是求解器结束）记录“重算基线”（仅当上一份完整路线预计结束战斗且上一回合由求解器结束），清空续接，重新捕获搜索根。
5. 主线程编译请求，后台按组合调度跑搜索成员。搜索线程按检查点发布推演候选和当前回合预览，节流 200 毫秒；工作线程只做展开。整次请求的进度预算按协调器实际规划的成员时限求和；有整次截止时间时使用截止时间。
6. 搜索完成后回放路线，核对搜索开始时的 `CombatStateStamp`。状态、可解性或戳不一致的结果被丢弃。
7. 停止搜索时，协调器把已完成成员的最优结果和当前候选按最终排序比较，取更优的一条；该路线经过现有重放校验后直接成为本回合路线和续接来源。停止发生在某一遍的中间成员时，协调器同时带出一份只在宿主内存里的接续状态；停在最后一遍的最后一个成员时不带接续状态。被停成员没有任何候选、但前面已有完成结果时，采用已完成的最优结果并按停止返回。完全没有候选时取消搜索。接续状态和继续规则见[继续搜索](#继续搜索)。

### 继续搜索

停止搜索后，主线程保留协调器的接续状态、停止时的精确请求、局面戳和搜索设置快照。局面戳与停止时一致、设置快照也相等时，“继续搜索”可以按；否则它变灰，只能按旁边的“重新搜索”。显示判断只比较局面戳和设置值，不重新编译请求。

点“继续搜索”时再做一次精确核对：用当前局面和设置重新编译请求，和停止时的请求逐字节比较，完全相同才把同一份计划、同一个请求和接续状态交给协调器；不同就按“重新搜索”从头搜，并写日志说明请求的规则、根或选项哪一部分不同。继续时从被停成员的下一个开始，跑完剩下的成员和遍数，被停成员不重跑。每个剩余成员仍按原来的宽度乘每宽度毫秒计时，进度条的计划总时长改成剩下成员的总和。

剩余成员跑完后，协调器先按现有规则在它们之间选出最优，再和停止时采用的结果用同一套最终排序（`TryCompareResultQuality`）比较，取更好的。比较不出来（路线无法回放或评分）时保留停止时的结果，并在宿主日志里写明原因。继续期间面板保留停止时的最好路线，有更好的结果才替换；中途再停同样可以再继续，新接续状态保留两次停止中更好的结果。

接续状态在回合变化、开始执行、玩家出牌导致局面变化、战斗结束、退出场景和开始新搜索时作废。回合开始的准备选牌搜索是多根请求，暂不支持继续；停止后“继续搜索”保持灰色。继续搜索是玩家手动开始的搜索，搜完以后是否自动执行沿用“重新搜索”的规则，不新增规则。

### 回合开始的选牌

原版在玩家回合开始时先执行 `SetupPlayerTurn`。需要选牌时，玩家 `PlayerTurnPhase` 保持 `Start`，设置页面等待一个玩家选择上下文；这段等待不是动作队列里的一个动作，所以 `FinishedExecutingActions()` 可能已经完成。暂停时原版先跑侧回合开始和球，选择结束后 `RunAutoPrePlayPhase` 把阶段推进到 `AutoPrePlay`，再进入 `Play`。`CombatManager.TurnStarted` 可能在暂停期间就触发，也可能在进入 `Play` 后触发，所以控制器把两种顺序都当作“回合开始事件”，在 `PlayerTurnPhase` 到 `Play` 后才处理计划。

自动搜索开着或本场执行进行中时，会接管可见的回合准备页面，也会接管其后的 `RunAutoPrePlayPhase`。CombatSolver 同时加载时只有本场执行接管；只开自动搜索时按 `TurnSetupHandling.SearchOnly` 处理：同一个事务照样在入口导入 Start 根、在第一个可见页面出现后搜索并发布计划，但不替换 `SetupPlayerTurn`（CombatSolver 开着自动计算时会替换同一个任务）、不接管 `RunAutoPrePlayPhase`；玩家按执行键时照样驱动页面（和玩家亲手点一样），选完接着部署。玩家进入 `Play`（包括 AutoPrePlay 阶段的选择）即视为 setup 结束，事务随之收尾。两段共用同一个页面会话和同一份计划，搜索只启动一次：setup 和 AutoPrePlay 谁先看到第一个可见页面，谁就启动搜索。`PlayerTurnSetupRuntime` 在 `SetupPlayerTurn` 入口导入 Start 根，用 `TurnSetupRootEnumerator` 枚举 Play 根，再用 `CompileSetupRequest` 编译多根请求；计划可以包含 AutoPrePlay 阶段的选择。搜索不在入口启动，而是在第一张真正可见的 `CardSelectCmd` 页面出现后启动；页面在搜索期间不加输入遮挡，玩家可以自己选。没有可见页面的纯隐式选择（例如手里只剩一张牌的烘焙手套）不启动准备搜索，原生自动选完后在 `Play` 照常搜索。混合场景里如果某个隐式请求在侧回合开始后变成了可见页面，观察层会把它提升为可见请求；手牌候选在暂停后重新读取，侧回合开始新增的牌（例如十字弓生成的攻击）会进入候选并参与枚举和计划匹配。

不在本场执行中时，搜完只发布路线和计划，不点页面；玩家可以自己选，或按“执行本回合”“执行本场战斗”让求解器在页面上点完再部署。本场执行中搜完直接驱动；驱动前评估和普通回合相同的两个暂停条件（“预计本回合死亡” `death_turn`，包括只有死亡路线；本场第一次出现“未找到生还路线” `no_survival`），命中时不点页面、把页面交还玩家并暂停本场执行，路线只作为建议显示。玩家在搜完前自己选了，本次搜索作废，进入 `Play` 后按普通流程处理。AutoPrePlay 的页面按同一规则处理：不在本场执行中只显示，本场执行中在未预计死亡时驱动。

### 后续回合沿用计划

上一回合由求解器部署、并且路线里上一回合的 EndTurn 动作带有本回合 `PlayerTurnStart` 时机的选择（包括 AutoPrePlay 阶段的选择）时，先在 `SetupPlayerTurn` 入口校验这份计划，再决定是否沿用：从导入的 Start 根用 `Kernel.PreparePlayerPlayPhase` 按计划选择重放前奏，逐段比较候选 id、升级、顺序和最少/最多选择数，再按续用比较的口径比较重放出的 Play 根和上一回合 EndTurn 的 `After`。

两项都通过才沿用：先等第一张可见页面，再把这份计划标为就绪。不在本场执行中时显示“等待回合开始选择”和这份路线，玩家可以自己选，或按执行键让求解器点完再部署；本场执行中在未预计本回合死亡时直接驱动。驱动前的死亡判断和正常准备计划完全一样。校验不通过时丢掉沿用计划，直接走新的准备枚举和搜索；日志分别写候选不同、Play 根不同或重放失败，不暂停本场执行。页面上的“重新搜索”也会丢弃沿用计划，从 Start 根重新枚举并在同一个页面上开一次准备搜索。

上一回合的 EndTurn 预测“本回合准备页选完后战斗就结束”时，路线里没有本回合的动作，所以没有沿用计划，本回合照常枚举并搜索；选完就获胜的终局分支目前不作为搜索根，搜索在其余分支里选。部署器等待这个 EndTurn 的终局边界时，原生战斗如果没有结束、而是进入了下一回合的 `Play`，就停止等待（稳定 0.5 秒后）：准备页面已接管时按“被准备计划取代”处理，由准备计划执行本回合；否则按结束回合偏差暂停。出牌或用药预测战斗结束而原生战斗还在进行时，按 `combat_continued` 执行失败处理。等待终局边界也受 180 秒边界超时约束，不再无限等待。

已经驱动页面后才发现页面请求与计划对不上、或计划里的牌在页面上找不到时，求解器不猜：释放页面交还玩家；本场执行中按 `choice_mismatch` 暂停本场执行，路线不再保留。

选完后进入 `Play` 时仍走普通的路线续用比较：实机状态和上一份完整路线的当前回合边界一致就裁剪并复用。上一回合由求解器结束、这份续接路线又对不上时按 `boundary_deviation` 停下；上一回合不是求解器结束（例如玩家自己结束）时只丢弃过期路线并重新搜索。

驱动只在点击和确认期间加全屏输入遮挡，驱动结束、停止、失败、战斗结束或退出场景时释放。停止搜索时如果已有候选，保留计划并交还页面；没有候选就清掉计划。停止执行会在下一次点击或确认前停住。失败使用独立错误码 `turn_setup_failed`，替换任务正常结束，不把原生 `StartTurn` 弄成 fault，页面仍由原生代码等待。

准备结果在进入 `Play` 时用搜索时保存的精确 `CombatStateStamp` 与实机状态比较；只有计划确实由求解器驱动、并且戳完全一致时才激活或复用。求解器驱动页面后戳仍不一致时按 `boundary_deviation` 停下，不重搜；玩家自己选了或戳导入失败时仍丢弃计划并按普通流程处理。这样侧回合开始、球和监听器改变状态时不会部署一条从错误局面出发的路线。

## 一次执行

1. 只取路线的当前回合动作；结束回合单独处理。
2. 每个动作经 `ActionDeployer` 走原版动作队列，完成后重新导入实际状态，和路线预测逐字段比较。
3. 动作结果与预测不同时立刻停下（`action_deviation`）：不再发出新动作，正在结算的动作照常走完，丢弃剩余路线和续接来源，不自动重新搜索。
4. 执行下一个动作前核对回合、能量、星能、手牌数量与身份、药水、目标和选择。对不上时同样停下（`deployment_deviation`），不再猜，也不自动重新搜索。其它无法执行的原因（动作无法入队、动作抛异常/被取消、原生状态缺失、边界等待超时、实机导入失败等）按 `deploy_failed` 停下，也不自动重搜。部署的选择器在原生异步选牌任务里运行，计划外请求不抛异常：记录 `choice_mismatch`，当前手牌选择交还原生界面（无头测试没有界面时用保底候选让流程走完），当前动作结算到边界后控制器按 `choice_mismatch` 停下并计一次部署失败。准备页的 Harmony 观察补丁、回合准备补丁和生命周期回调也统一经过 `NativeCallbackGuard`；意外异常只记录并暂停，不进入游戏的原生任务。
5. 全部动作完成后才提交结束回合。本场执行中，结束回合前做一次实机复核：从当前导入状态用 `Kernel.Step` 模拟这个结束回合，实机死亡或战损大于路线计划值时按 `live_end_turn_risk` 暂停。这个复核在本场执行中始终生效，没有开关；执行本回合不做这个复核。
6. 上一回合由求解器结束、本回合开始时有续接路线但对不上实机时，按 `boundary_deviation` 停下。上一回合不是求解器结束（例如玩家自己结束）时，路线过期只丢弃并按普通流程重新搜索。
7. 路线没有当前回合动作时按“计划耗尽”（`PlanExhausted`）重新搜索；这条路径不暂停。

逐动作执行前会核对回合、能量、星能、手牌数量与身份、药水和目标；选择的数量和选项必须和游戏当前请求一致，对不上就不猜。

### 结束回合与下一回合的准备

`ActionDeployer` 执行结束回合动作后，如果下一回合可能请求准备选择（同一套快速门：自动档、单人、战斗进行中、`RequiresSolverChoice` 对下一回合为真），会把 `PlannedNativeSelector` 留到敌方回合结束，由下一回合的准备拦截（`TryInterceptSetup`）在检查 selector 之前释放。敌方回合里提出的计划选择（知识恶魔的 CURSE_OF_KNOWLEDGE）因此仍由这条路线回答；之后原生准备页能以 `CardSelectCmd.Selector == null` 出现，交给 setup 事务；没有准备内容的战斗仍在边界等待期间保持 selector，行为和以前相同。结束回合的内核预测和这次释放保持一致：Mod 导入搜索根时按同一个接管门（`PlayerTurnSetupRuntime.NextTurnChoicesPause`）设置 `BattleFlags.TurnStartChoicePauses`。接管时普通 EndTurn 在第一个回合开始选择处暂停，和可见准备页的 `PreparePlayerPlayPhase` 重放一致；不接管时按 selector 立即回答、不暂停。比对导入沿用预测里的这一位。`ts-g-multi-choice` 的熔炉在可见准备页暂停处多出的候选因此已经在上一回合的计划里，沿用校验通过，不会落入入口校验失败后的新搜索。

额外回合（PaelsEye、AmbergrisPower）的回合准备走同一条接管和沿用路径：额外回合事实来自原生 `CombatTurnState.PlayersTakingExtraTurn`；普通 EndTurn 与额外回合的预测都按 selector 是否释放（`TurnStartChoicePauses`）走对应顺序，准备根、候选枚举和沿用校验都带这个事实，不需要另建一套流程。

上一回合的部署被下一回合 setup 接管时标记 `SupersededByTurnSetup`：结束回合的实机边界不再和旧路线比较，不计偏差、不重搜，下一回合由 setup 的结果接手。下一回合优先沿用上一回合 EndTurn 动作里的 `PlayerTurnStart` 计划；没有可沿用的选择时才从 Start 根枚举并搜索。

下一回合的准备根携带最近一次已核对的预测边界（上一回合 EndTurn 动作的 `Before`）里的非原生账本：成长额度用量、自动/生成用药计数、免死计数与回血、`RecoveredHp`、`LongTermResourceValue` 和复活中的敌人行。准备接管时如果上一回合的部署结果还在，先用内核把这个 EndTurn（带旧路线的选择）推进到下一回合玩家 `Phase == Start`，和实机 `ImportSetupRoot` 逐字节比较：一致就用预测 Start 根，不一致记一条 `TURN_SETUP_START_PREDICTION_MISMATCH` 并退回实机导入（仍带同一份已验证账本）。两种口径都遵守回合准备根自己的事实：`VitalSparkNormalizedAmount = 0`、`ShuffleEventCount = 0`，`HasRisk` 从 tracker 继承。原生可重建的计数（例如 `CumulativeHpLost`、`OrbChannels`）仍从实机 History 读取。

### 停止执行

部署会话带一个软停止标记，在每个动作开始前和结束回合前检查。点“停止执行”只设置标记，不取消动作令牌；已发出的动作连同它的选牌、边界等待和稳定等待走完后，部署才返回“已停止”。在此之前 `_deployment` 保持非空，底栏的“停止执行”处于停止中的禁用态，左槽也不能搜索。

能保证的是：不再发出新动作；已发出的牌会结算完。不能保证的是：已经发出的“结束回合”可以收回，或者正在结算的动作会立即中断。战斗结束、退出场景和重置仍走现有的硬取消。

## 停止与暂停

停止搜索和停止执行都记“本回合不再自动”，沿用 `_automaticSearchPaused` 和回合号；停止执行同时结束本场执行。它们不修改自动搜索开关；下一回合照常按开关走。停止搜索会留下本回合的接续状态，是否显示“继续搜索”见[继续搜索](#继续搜索)。

本场执行在展开路线后、开始执行前有两个暂停条件：路线预计本回合死亡（`death_turn`）时总是暂停；路线在之后的回合死亡（未找到生还路线，`no_survival`）时每场只暂停一次，玩家按“执行本场战斗”继续后，本场不再因远期死亡暂停，只保留 `death_turn`。路线既没有胜利也没有死亡（搜到上限还没有结局）时不暂停。结束回合前的实机复核始终生效：实机死亡或战损大于路线计划值时按 `live_end_turn_risk` 暂停。暂停条件命中时：

- 本场执行结束（`_runCombat` 清掉，`_runPaused` 置位），路线保留，两个执行键回到原位；
- 后续回合按自动搜索开关走，只是不再自动执行；
- 再按“执行本场战斗”等于确认当前路线：清掉暂停，这一回合跳过刚才那项检查，之后照常检查；
- 下一场战斗开始时本场执行是关的，要玩家再按。

求解器自己执行时发现实际结果或局面和预测不一致，会立即停下，执行本回合和执行本场战斗都一样。停下时不再发出新动作，正在结算的动作照常走完；丢弃剩余路线和续接来源，不调用 `RequestSearch`。阶段是 `Paused`，暂停码是 `action_deviation`（动作结果不同）、`deployment_deviation`（发下一个动作前发现牌、药水、目标或回合对不上）、`boundary_deviation`（上一回合由求解器结束，本回合续接路线对不上，或准备计划点完后实机戳对不上）或 `deploy_failed`（部署动作无法执行）。摘要先写暂停标题，再写一行具体原因：偏差按 Battle 差异字段说明是手牌、能量、星能、药水、回合、敌人、能力、遗物、生命还是牌堆和路线对不上；部署失败按原因码说明是原生动作出错、动作未入队、等待超时、找不到战斗状态还是读回状态失败。本回合不再自动搜索；本场执行中同时结束本场执行并标成暂停。搜索键可用，执行键在原位但变灰，由玩家决定是否重算。

`choice_mismatch` 也把本场执行标成暂停。暂停统一清除续接来源。暂停码只有 `death_turn`、`no_survival`、`live_end_turn_risk`、`repeated_failure`、`choice_mismatch`、`action_deviation`、`boundary_deviation`、`deployment_deviation`、`deploy_failed` 和 `stopped`；命令拒绝原因写入单独的 `rejectCode` / `SearchBlockReason`。`repeated_failure` 只用于搜索失败；偏差和部署失败都直接停下，不再累计到 3 次。

实机复核暂停发生在部署之中、结束回合之前。暂停时控制器把剩下的计划（只剩结束回合）保留为本回合路线并更新实机戳，所以两个执行键仍然可用：“执行本回合”强制执行这一回合；“执行本场战斗”确认后跳过这次复核继续。

### 搜索失败

搜索在导入根、编译请求、搜索或回放路线时失败，或者没有返回可执行路线时，控制器把阶段设为 `Failed`，把稳定错误码写进快照并发布。主面板状态行显示“求解器消息”，摘要显示 `SolverPanelText.Error(码)`：导入失败显示“搜索初始化失败”，搜索失败显示“搜索失败”。标题下面再显示一行具体原因，由快照里的结构化原因（导入原因、容量区域与上限、协调器状态或内存标志）映射成玩家文案，不解析异常消息；例如牌数超过容量时写实际张数和 `Limits.Cards`，搜索丢弃过超容量分支且连一条可执行路线都没有时写“生成的牌太多，超出求解器容量，没有找到能赢的路线”。没有映射的原因只写“详细原因已写入日志”，完整 `code` 和诊断细节仍写进游戏日志。路线隐藏，执行键在原位但变灰，“重新搜索”可以点。

搜索丢弃过超容量分支、但仍有非胜利路线时不再判失败：协调器把最好的 `Defeat` / `Incomplete` 路线按普通结果返回，路线照常显示和执行，本场执行也照常执行；只有没有任何路线时才保持 `CapacityBounded` 失败。这种情况下路线摘要下面会多一行“部分打法因…超出求解器容量被跳过，可能还有更好的路线”，区域名按实际容量区域显示（牌数或其它区域）。

失败不会在同一回合自动重试，也不执行半成品路线。搜索失败在同一回合累计到 3 次时按 `repeated_failure` 暂停；部署失败按 `deploy_failed` 立即停下，偏差按对应的偏差码立即停下，都不进入这个计数。失败状态在下一次搜索开始、回合变化或战斗结束时清除。

## 什么时候停

- 求解器执行时实际结果或局面和预测不一致：立即停下（`action_deviation`、`boundary_deviation` 或 `deployment_deviation`），不自动重搜，由玩家决定是否点“重新搜索”。
- 部署动作无法执行（`deploy_failed`）时同样立即停下，由玩家决定是否重搜。
- 本场执行中预计本回合死亡（`death_turn`）、本场第一次未找到生还路线（`no_survival`）或结束回合前实机复核发现死亡/更大战损（`live_end_turn_risk`）时暂停并结束本场执行，自动搜索开关和后续回合的自动搜索不变。
- 搜索结果过期（当前状态、可解性或精确局面戳变化）时丢弃，不自动重搜。
- 搜索失败在同一回合累计到 3 次时暂停（`repeated_failure`），本场执行结束，自动搜索开关和后续回合的自动搜索不变。计数在回合变化、本回合成功结束、手动搜索时清零。
- 路线没有当前回合动作时重新搜索（`PlanExhausted`），不暂停。
- 战斗结束或退出场景时硬取消搜索与执行。

## 快照保鲜

`Pump` 在空闲时也按帧检查回合方、阶段和动作队列。动作队列由忙转闲、回合或阶段变化时，重新核对本回合路线是否仍和实机一致；只有搜索键、执行键或原因码变化时才发布新快照。这样玩家手动出牌后，执行键不会继续亮着一条过期路线。

## 配置注入

`CombatSearchRunner` 可以接收一个在主线程上调用的策略配置函数，测试侧用它设置固定的请求参数。生产代码不接收测试场景 DTO，也不依赖 TestHost。搜索热路径不读取任何全局设置，配置只能在捕获请求时注入。
